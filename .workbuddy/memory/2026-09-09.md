# 2026-09-09

## 部署迁移：Netlify(提交 public/) → GitHub Pages（Actions 直接部署）

- 背景确认：原流程 `export-weread-notes.yml` 每天/每次 push：导数据 → Hugo 构建 → **把 public/ 提交回 main** → Netlify 直接托管仓库里的 public/。运行全部成功，用户的诉求是让 Actions 构建后直接上传部署，不再提交构建产物。
- 用户选择：迁移到 GitHub Pages（自定义域名 blog.zzek.cn 保留）。
- 改动：
  1. 重写 `.github/workflows/export-weread-notes.yml`：permissions 增加 pages:write + id-token:write；concurrency 组改 "pages"；Hugo 版本从 latest 固定为 0.165.0（与本地一致，防模板行为漂移）；新增 actions/configure-pages@v5（enablement:true，continue-on-error）→ `hugo --gc --minify` → 机器人**只提交数据与内容**（static/data/*.json、content/weread/、content/memos/，不再 add public/）→ actions/upload-pages-artifact@v4（path ./public）→ actions/deploy-pages@v4。机器人提交仍带 [skip ci] 防循环。
  2. 新增 `static/CNAME`（内容 blog.zzek.cn），随构建进入产物根目录，让 GitHub Pages 记住自定义域。
- 用户侧切换步骤（告知）：① push 后确认 Actions 首次部署成功（若 Pages Source 未自动设为 GitHub Actions，去 Settings→Pages 手动设）；② DNS 把 blog CNAME 从 Netlify 值改为 `ilikui.github.io`，等证书签发后开 Enforce HTTPS；③ 切换稳定后清理：`git rm -r --cached public` + `.gitignore` 加 `public/`（并更新其中关于 Netlify 的注释）+ 推送，然后解绑/删除 Netlify 站点。
- 注意：在步骤③之前不要把 public/ 移出 git——Netlify 还在托管提交的 public/，过早删除会导致旧域名立即 404。
- 验证：workflow YAML 语法通过 pyyaml 校验；本地 `hugo --quiet` 构建通过且 public/CNAME 存在。
